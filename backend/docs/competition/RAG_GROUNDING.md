# AlgoPilot 课程知识库约束与来源解释

## 为什么需要知识库约束

比赛评审不仅关注资源是否“能生成”，也关注内容是否可追溯、可解释、可复核。若只展示大模型正文，评委无法判断内容来自课程材料还是模型记忆，也难以识别虚构章节、题号、外链和错误复杂度结论。

AlgoPilot 因此将课程知识库切片作为资源生成的显式依据。每份新资源保存 2-5 条 `sources`，包含切片 ID、模块、章节、知识点、源文件、相关度和摘要。资源详情可直接展示这些信息。

## 检索—生成—校验流程

1. **检索**：`KnowledgeRetriever` 使用 BM25 和同义词扩展，根据主题、模块和章节选取 Top-K 课程切片。
2. **生成**：角色 Agent 接收学生画像、协作上下文和检索片段，只在课程上下文约束下生成资源。
3. **校验**：`ContentVerifierAgent` 先执行规则快检，再在模型可用时对照相同知识片段检查事实一致性。
4. **安全审查**：`SafetyAgent` 检查敏感内容、提示词注入和其他风险。
5. **持久化**：正文、`sources`、`content_verification` 和综合 `verification` 一起写入 `GeneratedResource.meta`。

`content_verification` 对外展示：

- `passed`
- `warnings`
- `grounded_terms`
- `unsupported_claims`

## 如何降低幻觉

- 生成 Prompt 注入课程原文切片，而不是只传章节名称。
- 保存并展示实际命中的来源，不根据生成正文反向伪造引用。
- 拦截知识库未提供的外链和可疑四位题号。
- 检查复杂度结论是否缺少适用前提。
- 校验失败时将资源标记为草稿，并把修订建议回流给生成 Agent。
- 模型或校验服务不可用时使用课程模板降级，并显式标记，不冒充大模型原创。
- Trace 等不适合文本事实校验的资源仍保存生成依据模块和来源切片。

## 当前限制

- 当前相关度是单路 BM25 分数在本次候选集内的归一化结果，适合解释排序，不等同于概率。
- 中文分词采用轻量规则和同义词扩展，对长尾表达、隐含语义和跨章节关联的召回有限。
- `ContentVerifierAgent` 能发现明显冲突和无依据声明，但不能替代教师最终审核。
- 历史资源可能只有 `knowledge_refs`，前端会兼容展示 source id，但无法恢复当时未保存的相关度和摘要。

## 后续混合检索计划

后续可在不改变 `sources` 数据契约的前提下扩展为：

`BM25 召回 + Embedding 语义召回 + Reranker 重排`

建议先并行召回候选，再去重和重排，最终仍只保存 2-5 条实际进入生成上下文的来源。Embedding 服务应作为可选增强，不能成为课程资源生成的单点依赖；离线或服务异常时继续使用 BM25。
